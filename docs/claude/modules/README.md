# Module notes

One file per module: how it's built now. Covers the main classes and services, tables, jobs and schedules, routes, outside services and their config, test helpers and fakes, and demo data. Write it for the next session that has to change the module.

- Each file is linked from `CLAUDE.md` → Module notes (the docs check fails if one isn't).
- Keep it current in the same PR as the code. It describes the present, not history. Decisions go in `../decisions/`, and phase history in the phase docs.
- Start a module's file when it gets substantial work.
